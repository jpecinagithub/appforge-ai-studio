# Auditoría técnica de AppForge — 13/10/2026

## Alcance

Esta auditoría cubre exclusivamente `jpecinagithub/appforge-ai-studio` y el
despliegue `https://appforge-ai-studio-six.vercel.app/`. GameForge es otro
proyecto y no forma parte de estos cambios.

Se revisaron el Studio React/Vite, el servidor Fastify, el worker/agente, el
modo demo y la conectividad pública con el backend Oracle.

## Hallazgos corregidos

1. **El agente podía finalizar con éxito después de fallar el build.** Los
   fallos de `install_dependencies`, `run_build` o `start_preview` quedaban en
   el historial, pero una respuesta final del LLM marcaba el run como `done`.
   Ahora los fallos críticos pendientes bloquean la finalización y los cambios
   de archivos exigen una preview verificada.
2. **`npm` no se ejecutaba con `shell: false` en Windows.** `execFile` intentaba
   lanzar el wrapper `.cmd`, fallaba inmediatamente y la prueba de ciclo
   completo lo detectó. Ahora se ejecuta el CLI JavaScript de npm/npx con el
   binario Node actual, manteniendo el aislamiento sin shell.
3. **Las previews del modo demo estaban vacías.** Los proyectos demo declaraban
   una preview lista, pero `/p/demo-*/` no existe en Vercel. Se añadieron
   previews autocontenidas y funcionales para Tic-Tac-Toe y Task Board,
   incluyendo interacción real.
4. **Sandbox de preview demasiado permisivo.** Se combinaban
   `allow-scripts` y `allow-same-origin` para contenido generado. Se eliminó
   `allow-same-origin` para evitar que código no confiable comparta el origen
   privilegiado del Studio.
5. **Mensaje de sesión caducada incorrecto.** Un primer `401` sin credenciales
   se mostraba como contraseña inválida/sesión caducada. El estado distingue
   ahora entre login requerido, logout y rechazo de una credencial previa.
6. **Vercel Analytics rompía la consola cuando no estaba habilitado.** El
   catch-all devolvía `index.html` para `/_vercel/insights/script.js`, causando
   `Unexpected token '<'`. Analytics es ahora opt-in mediante
   `VITE_VERCEL_ANALYTICS=1`.
7. **Construcción insegura de la URL de preview.** Se normaliza la barra final
   de `VITE_API_URL` y se codifica el id del proyecto como un único segmento.
8. **Dependencias de test vulnerables.** Vitest 3 arrastraba vulnerabilidades
   críticas en `tinypool` y una lectura de rutas en `@vitest/mocker`. Se
   actualizó a Vitest 5.0.4. La dependencia transitiva DOMPurify del editor se
   fijó a una versión corregida. `npm audit` queda en cero vulnerabilidades en
   backend/worker y Studio.
9. **Runtime de Oracle desalineado.** El proyecto exige Node 24, pero la imagen
   del backend todavía partía de Node 22. El Dockerfile usa ahora Node 24 para
   que instalación y ejecución respeten el contrato declarado en `engines`.

## Evidencia de validación

- Suite backend/worker: **21/21 tests pasan**.
- Tests nuevos del Studio: **3/3 pasan**.
- Typecheck backend/worker: **correcto**.
- Build de producción del Studio: **correcto**; tras separar las rutas, el
  bundle inicial queda en 334.32 kB JS / 105.48 kB gzip.
- Smoke test visual: Dashboard, Projects, Create App, Library, Assets, Builds,
  Revisions, Settings y dos vistas de proyecto cargan sin estado de error.
- Preview Tic-Tac-Toe: movimiento del usuario y respuesta de la IA verificados.
- Preview Task Board: contenido y controles verificados.
- Consola de la compilación corregida: sin errores ni warnings en el recorrido.
- Backend Oracle: accesible por HTTPS; `/api/health` responde `401` sin token
  con el sobre JSON esperado; el preflight CORS desde Vercel responde `204` y
  permite `authorization,content-type`.
- CI añadida en `.github/workflows/ci.yml`: instalación reproducible, tests,
  typecheck, lint sin warnings, build y auditoría de dependencias.
- Las rutas del Studio se cargan de forma diferida. El bundle inicial bajó de
  **421.06 kB a 334.32 kB** (de 126.83 kB a 105.48 kB gzip); ProjectView y las
  páginas secundarias quedan en chunks independientes.
- Los 20 avisos previos de Oxlint quedaron resueltos o documentados como
  excepciones deliberadas para providers y ciclos de carga asíncrona. CI usa
  `--deny-warnings` y también detecta supresiones obsoletas.

## Trabajo pendiente recomendado

### P1 — antes del siguiente despliegue

- Desplegar el commit del frontend en Vercel y el worker/servidor en Oracle de
  forma coordinada; el código local ya está validado, pero producción aún sirve
  la versión anterior.
- Ejecutar un E2E autenticado contra Oracle con un token de prueba: crear
  proyecto, ejecutar agente, build, preview, revisión y descarga ZIP. No se
  realizó porque no se proporcionó una credencial de administración.
- Añadir tests de componentes para Login/Auth, Workspace y navegación, además
  de pruebas responsive automatizadas.

### P3 — producto

- La acción Deploy sigue deshabilitada y correctamente etiquetada como Fase 3.
- Añadir persistencia opcional al Task Board demo solo si la preview se sirve
  desde un origen separado; no debe recuperarse `allow-same-origin` en el
  iframe del Studio.
